# 資料格式版本規則(schemaVersion)

> 2026-08-27 定案。網頁版與 iOS 版**必須同時採用同一條規則**,規則本身不可單方面更改。

## 規則(全部就這四條)

1. **讀取:`1.x` 一律試讀。** 版本號開頭是 `1.` 的檔案不因小版號不同而拒收。
2. **未知欄位原樣保留。** 讀到不認識的欄位不刪除、不報錯;編輯後寫回時原樣帶著(兩端都必須做到 —— 網頁版已實測整條路徑保留)。
3. **新增「選填」欄位不改版號。** 加欄位照常標 `1.0`;只有出現「不加新欄位就無法正確理解舊欄位」的變更,才升小版號並在本檔記錄。
4. **大版號 = 不相容。** 只有 `2.x` 才允許拒收,而且要附使用者看得懂的說明與升級路徑。

## 為什麼

一人維護兩個平台,版本一定會走岔。嚴格比對版本號的話,任何一端先加欄位,另一端的所有使用者收到同事傳的檔就是「打不開」——事故發生在資料交接的信任時刻。寬容讀取 + 欄位保留,讓兩端可以各自前進而不互相絞殺。
